# チャット機能 実装計画

- 日付: 2026-07-14
- ステータス: 承認済み

## 依頼内容

ユーザー同士のチャットを実施するような画面を作りたい。
- チャットの基本機能: メッセージ送受信、相手ユーザー選択、メッセージ一覧表示
- サイドバーに「チャット」リンクを追加する
- 既存のダークテーマに合わせた UI にする

## 実装計画

### リアルタイム通信方針

WebSocket（Socket.io）ではなく **HTTPポーリング** を採用する。
理由: 既存スタックに WebSocket の依存関係がなく、追加インストールと NestJS Gateway 設定が必要になる。SQLite + ポーリング（3秒間隔）で開発環境では十分な UX が実現できる。

### DBスキーマ変更

ChatMessage テーブルを追加:
```prisma
model ChatMessage {
  id          Int      @id @default(autoincrement())
  from_user   String
  to_user     String
  content     String
  created_at  DateTime @default(now())
  sender      Account  @relation("ChatSender",   fields: [from_user], references: [username])
  receiver    Account  @relation("ChatReceiver", fields: [to_user],   references: [username])
}
```

Account モデルに以下のリレーションを追加:
```prisma
sent_messages     ChatMessage[] @relation("ChatSender")
received_messages ChatMessage[] @relation("ChatReceiver")
```

### バックエンド実装ステップ

1. Prisma スキーマに `ChatMessage` モデルと `Account` のリレーション追加
2. `src/chat/dto/chat.dto.ts` — CreateChatMessageDto（to_user, content）/ ChatMessageResponseDto
3. `src/chat/repository/chat.repository.ts` — findConversation / create / findContacts
4. `src/chat/service/chat.service.ts` — ビジネスロジック（送信・取得）
5. `src/chat/controller/chat.controller.ts` — GET /chat/contacts / GET /chat/messages?with=<username> / POST /chat/messages
6. `src/chat/chat.module.ts` — モジュール定義
7. `src/app.module.ts` — ChatModule を imports に追加
8. `src/common/type/message.ts` — CHAT セクション追加
9. `src/accounts/repository/account.repository.ts` — findAll() メソッド追加（全ユーザー一覧取得）
10. AccountsModule に AccountRepository をエクスポート追加

### フロントエンド実装ステップ

1. `src/api/chatApi.ts` — fetchContacts / fetchMessages / sendMessage / fetchAllUsers
2. `src/hooks/useChat.ts` — チャット相手選択・メッセージ一覧・ポーリング（3秒）・送信
3. `src/pages/ChatPage.tsx` — チャット画面（左: ユーザーリスト、右: メッセージ一覧 + 入力欄）
4. `src/components/Sidebar.tsx` — NAV_LINKS に /chat → チャット を追加
5. `src/App.tsx` — /chat → ChatPage ルート追加

## レビュー結果

- 既存アーキテクチャ（Controller → Service → Repository → Prisma）に準拠
- JWT認証（JwtAuthGuard）を全エンドポイントに適用
- DBスキーマ変更は ChatMessage 1テーブルで最小限
- フロントエンドが既存パターン（pages/hooks/api の分離）に準拠
- ダークテーマ: 既存 Tailwind クラス（slate系）を使用
- ポーリング間隔: 3秒（過剰なDB負荷にならない範囲）
- リスク: なし
