# Claude Code 使い方ガイド

## Claude Code とは

ターミナルから操作するAIコーディングエージェント。
このプロジェクトでは `/implement` コマンド一つで「計画 → レビュー → 実装 → テスト → コミット」まで自動で行うエージェントフローが構成されている。

## 起動

```bash
claude          # 対話モードで起動
claude "質問"   # 一言で聞く
```

## よく使うスラッシュコマンド

| コマンド | 用途 |
|---------|------|
| `/implement <依頼内容>` | 機能追加・修正・リファクタリング（エージェントフロー全体を起動） |
| `/commit` | 現在の変更をコミット（メッセージ自動生成） |
| `/create-agent <概要>` | エージェントまたはスキルを作成・修正する |
| `/review` | 現在のブランチのPRをレビュー |
| `/security-review` | セキュリティ観点でのコードレビュー |
| `/init` | CLAUDE.md の初期生成 |

## `/implement` のエージェントフロー

`/implement` を実行すると以下の順でサブエージェントが自動的に動く。
各ステップに**承認ゲート**があり、ユーザーが確認してから次へ進む。

```
/implement <依頼>
     │
     ▼
┌─────────────────────┐
│  plan-creator-agent  │  コードを読み込み、実装計画を作成
└──────────┬──────────┘
           │ 承認ゲート①：計画確認
           ▼
┌─────────────────────┐
│  plan-review-agent   │  計画の妥当性・抜け漏れ・リスクを評価
└──────────┬──────────┘
           │ 承認ゲート②：レビュー結果確認
           ▼
┌─────────────────────────────────────────┐
│  frontend-generator-agent               │  フロントエンドの実装
│  backend-generator-agent                │  バックエンドの実装
│  （変更対象に応じていずれか or 両方）     │
└──────────┬──────────────────────────────┘
           │ 承認ゲート③：実装コード確認
           ▼
┌─────────────────────┐
│  test-agent          │  Jest ユニットテストを作成・実行
└──────────┬──────────┘
           │ 承認ゲート④：テスト結果確認
           ▼
┌─────────────────────┐
│  source-review-agent │  規約準拠・型安全性・セキュリティをレビュー
└──────────┬──────────┘
           │ 承認ゲート⑤：レビュー指摘確認
           ▼
┌──────────────────────┐
│  design-updater-agent │  detailed-design/ を実装内容に合わせて更新
└──────────┬────────────┘
           │ 承認ゲート⑥：設計書更新確認
           ▼
┌─────────────────────┐
│  commit-agent        │  コミットメッセージ自動生成 → git commit
└─────────────────────┘
```

## 承認ゲートへの応答方法

オーケストレーターが各ステップで確認を求めてくる。
**`SendMessage` で返答する**（新しいメッセージを入力する）。

### 承認する場合

```
承認
ok
問題ない
進めて
```

### 修正を要求する場合

```
〇〇の部分を△△に変えてほしい
〇〇は不要
```

修正を要求すると、該当のエージェントが修正して再度確認を求めてくる。

> **注意:** オーケストレーターから承認を求められたとき、自分でサブエージェントを呼び出さないこと。
> 承認か修正指示だけを返せば、オーケストレーターが続きを制御する。

## 規約の自動更新

以下のタイミングで `.claude/guidelines/conventions.md` が自動更新される。

| タイミング | 更新内容 |
|-----------|---------|
| コードへの直接指摘（「〜にして」「〜は使わないで」） | 指摘内容をルールとして追記 |
| 承認ゲートでの修正要求 | 却下内容をルールとして追記 |
| アプローチの承認（暗黙のOK） | 採用パターンとして追記 |
| 「やめておく」「不要」など否定 | そのアプローチを採用しない旨を追記 |

規約が蓄積されることで、次回以降の実装がプロジェクトのスタイルに自動的に沿うようになる。

## 実装依頼のコツ

### 具体的に書く

```
# 悪い例
タスクページを改善して

# 良い例
タスク一覧ページに検索バーを追加して。
入力するとタイトルと説明文でフィルタリングされるようにする。
バックエンドAPIは変更不要で、フロントエンドのみ対応。
```

### 変更範囲を伝える

```
フロントエンドのみ変更して
バックエンドのみ変更して
DB変更なし
```

### 参照ファイルを伝える

```
src/hooks/useTaskList.ts を参考にして同じパターンで実装して
```
